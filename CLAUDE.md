# CLAUDE.md

## О проекте
Siteless (пакет `siteless-bot`, раньше `2gis-bot`) — Telegram-бот для поиска компаний без сайта (лидов) с телефоном. Бот закрытый: владелец (`OWNER_ID`) и пользователи, чью заявку он одобрил (таблица `access`).
Источник данных: Geoapify (Places и Geocoding API), а не 2GIS.
Стек: Node.js (ESM, `"type": "module"`), grammY, PostgreSQL (`pg`), dotenv. Фронтенд: Vue 3 + Vite + vue-router + vue-i18n (RU/EN/ZH), `@vercel/analytics`.
Хостинг: бот — Railway (`railway.json`), сайт — Vercel (`vercel.json`, функция `api/request-access.js`).

## Структура
- `bot.js` — все команды бота, поиск, пагинация, callback-кнопки, CSV-экспорт
- `db.js` — пул PostgreSQL, `initDb()` (создаёт таблицы), все SQL-функции
- `schema.sql` — схема БД (справочно; реальная схема создаётся в `db.js` → `initDb`)
- `index.html`, `src/` — фронтенд (Vue + Vite). Тексты сайта — только в `src/i18n.js`, на трёх языках (ru, en, zh) с одинаковым набором ключей. Тема (светлая/тёмная) — `src/theme.js` и `data-theme` на `<html>`.
- `api/request-access.js` — Vercel-функция: заявка с сайта уходит владельцу в Telegram
- `public/` — статика
- `assets/` — иконка бота (`bot-icon.svg` — исходник, `bot-icon.png` — 512×512 для @BotFather)

## Команды
- `npm install` — зависимости
- `npm start` — запуск бота (`node bot.js`)
- `npm run dev` — запуск с перезагрузкой при изменениях (`node --watch bot.js`)
- `npm run frontend` — dev-сервер Vite
- `npm run build` / `npm run preview` — production-сборка и её просмотр

## Окружение (.env в корне, не коммитить)
- `API_TOKEN` — токен Telegram-бота (обязательна)
- `GEOAPIFY_KEY` — ключ Geoapify (обязательна)
- `OWNER_ID` — числовой Telegram ID владельца (обязательна)
- `DATABASE_URL` — строка подключения к PostgreSQL (обязательна)
- `DEFAULT_CITY` — город по умолчанию (по умолчанию «Алматы»)
- `MAX_PLACES` / `MAX_PLACES_KZ` — лимиты мест на поиск (по умолчанию 1500 / 3000)
- `DAILY_SEARCH_LIMIT` — поисков в сутки для одобренных пользователей (по умолчанию 10, на владельца не действует)
- В Vercel для формы заявки нужны `API_TOKEN` и `OWNER_ID`; `SITE_URL` — для своего домена в Open Graph
- `DATABASE_SSL` — `false` отключает SSL для БД
- `DATABASE_CA` — необязательная: PEM-сертификат провайдера БД (можно с `\n`); с ним сертификат сервера проверяется
- `OLLAMA_URL` / `OLLAMA_MODEL` / `OLLAMA_API_KEY` — необязательные: Ollama дописывает описание компании (модель по умолчанию `qwen2.5:3b`, ключ нужен только для ollama.com)
- `NODE_ENV=production` — включает SSL; без `DATABASE_CA` — с `rejectUnauthorized: false`
- `OLLAMA_API_KEY` отправляется только если `OLLAMA_URL` начинается с `https://`

Никогда не выводить значения этих переменных и не писать их в ответы, логи или код.

## Ключевая логика
- Лид = компания с телефоном и без «настоящего» сайта. Соцсети (instagram, t.me, vk и т.д.) считаются «без сайта» и показываются только при `with_social`.
- Мобильный номер: префиксы KZ (+7 70x/747/77x) и RU (+7 9xx). Флаг `only_mobile` оставляет только их.
- Поиск по всему Казахстану (`/search кафе Казахстан`) идёт по 20 регионам из `KZ_REGIONS`, лимит делится между ними. `place_id` регионов кэшируется в `regionCache`.
- Пустой результат в БД не сохраняется: иначе он затрёт прошлый поиск для `/last` и `/export`.
- CRM: в `contacted` у компании есть `status` (`contacted` → `replied` → `client` → `rejected`, кнопка с номером переключает по кругу, после `rejected` отметка удаляется вместе с заметкой) и `note` (`/note`). Компании с любым статусом в новых поисках скрываются.
- Доступ: middleware в начале `bot.js` пропускает владельца и пользователей со статусом `approved` в `access`. Новый человек при первом сообщении сразу попадает в `access` как `pending`, владельцу приходит заявка с кнопками; кнопка «Запросить доступ» — только для повторной заявки после отказа. Пользователи работают только в личке. Повторная заявка после отказа — не раньше чем через сутки.
- Лимиты для пользователей: `takeSearchSlot` (таблица `search_usage`, сутки по Алматы) и запрет поиска по всей стране. Владельца не ограничивать.
- Состояние сессий: `sessions` (Map в памяти) плюс БД. В callback_data кнопок лежит `searchId`, поэтому старые кнопки работают со своим поиском.
- Один поиск на чат: защита через `busy`. Поиск запускается в фоне (`startSearch`), чтобы бот не зависал.
- Описание компании (`leads.description`): `describePlace` собирает его из категорий и OSM-тегов Geoapify при поиске, ничего не придумывая. Если задан `OLLAMA_URL`, `describePage` в фоне дописывает описания открытой страницы до 20–50 слов, сохраняет в БД и перерисовывает сообщение. Дописанными считаются описания от 20 слов, и при новом поиске более длинное описание не затирается.
- Все пользовательские строки в HTML-сообщениях проходят через `esc()`: в боте стоит `parse_mode: "HTML"`.
- Безопасность: в CSV значения из OSM, начинающиеся с `= + - @`, получают `'` (защита от формул). Тексты внутренних ошибок видит только владелец, пользователю — `UserError` или общий текст. Ответ Ollama со ссылками или номерами отбрасывается. Уведомлений о заявках владельцу — не больше 20 в час. `sessions` хранит не больше 200 чатов.
- `api/request-access.js` принимает заявки только с `Origin` своего сайта и ограничивает частоту (3 за 10 минут с IP, 30 всего). Лимит в памяти экземпляра функции — от простого спама, не жёсткий.

## Правила при работе с кодом
- Не добавлять 2GIS API без явной просьбы.
- Не менять `MAX_PLACES` и `MAX_PLACES_KZ` по умолчанию: от них зависит расход лимитов Geoapify. Поиск по стране особенно дорогой, в тестах его не запускать без необходимости.
- Схема БД создаётся через `CREATE TABLE IF NOT EXISTS`. Миграций нет. Любое изменение таблиц нужно делать отдельным `ALTER ... IF NOT EXISTS` в `initDb` (и в `schema.sql`) и сначала спросить меня.
- В `updateSetting` есть белый список полей (`only_mobile`, `with_social`, `template`). При добавлении новой настройки добавлять поле и в `db.js`, и в список.
- Доступ проверяется middleware в начале `bot.js`. Не ослаблять эту проверку. Одобренные пользователи проходят middleware, поэтому админские действия (`/users`, `/revoke`, кнопки `access:ok/no`) дополнительно проверяют `isOwner` / `ownerOnly`.
- Не переписывать рабочие части без причины. Предпочитать простые решения и не добавлять лишних абстракций.
- Объяснения и комментарии — на русском.
